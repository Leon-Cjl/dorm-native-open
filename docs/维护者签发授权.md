# 维护者签发 .dormkey

此页留给维护者。对外发送 `onboarding` 文件夹即可；不要把 `private`、签名私钥、个人 APK 或本人页面证据放进公开包。

## 接收与核对

申请者在自己已登录的官方小程序内完成实际观测，其 AI 使用 `onboarding/session-export.cjs` 生成 `.dormrequest`，并随附其中列出的原始页面证据文件。

申请者AI从其本人的真实已登录页面取得资料，工具自动验证证据文件摘要和资料格式。此工具是你本地使用的迁移签发工具，不是远程身份认证或公共签名服务。

在原项目目录运行（Node.js 已有，无依赖安装）：

```powershell
node tools/issue-dormkey.cjs 待签发文件.dormrequest 证据文件夹 本人宿舍.dormkey
```

一条命令直接完成，没有确认弹窗，也不用复制摘要。程序重新向现有后台只读查询同一本人账号和所选房间，自动校验人员、组织、房间、设备和 MAC，再使用本机 `private/local-migration-signing.pem` 签名。只接受24小时内申请；不覆盖已有输出。密钥不匹配 APK 内公钥时会拒绝，不会改公钥或生成新密钥。

将生成的 `.dormkey` 私下交回对应本人，手机选中文件即自动绑定，无需“核对并切换”，之后由其本人到门旁测试。签发不发送开锁命令，也不增加学校后台权限；后续每次开锁仍按应用现有授权查询与有效期检查执行。

## 当前证据与限制

2026-11-07 已在维护者本人的电脑微信官方“我的”“我的房间”页面实际采集并完成只读查询及签发。此结果验证该本人现有学校/门锁资料的流程；尚未验证另一名新用户的首次导入。现版仍需你这边自动签发并返回文件，尚非无维护者参与的完全自助登录。

离线回归：`node tests/onboarding-tests.cjs`。不触网、不使用真实账号和私钥。公开源码中的公钥保持不变，私钥不进入源码 ZIP。
