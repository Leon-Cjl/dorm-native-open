# 用 AI 取得自己的宿舍文件

可采用这条路线：**本人登录小程序 → AI 处理资料 → 维护者工具自动签出 .dormkey → 手机选文件即绑定。** 不需要人工逐项核对、摘要确认或“核对并切换”，也不需要学校或微信新增导出按钮。程序仍自动检查实际权限和签名。

普通使用者把本文件夹和《给AI的指令.txt》交给能操作本机电脑的 AI，自己登录电脑微信“公寓智锁”即可。AI 会完成文件整理和命令操作。页面可以分在“我的”“我的房间”两处。不能读取电脑窗口的 AI，需要使用者本人提供对应页面截图。

## 两种文件，别弄反

- `.dormrequest`：由对方 AI 在其本人电脑生成的待签发资料。含本人学校、账号和所选宿舍的最少必要数据，还含对应页面证据的摘要。**尚不能导入 App。**
- `.dormkey`：维护者本地工具自动签发，现版 App 可导入。签名是本项目的迁移校验，既不是学校发卡，也不是官方身份证明。原有权限仍需通过后台查询校验。

现版 APK 内固定了项目签名公钥。另一台电脑的 AI 自己生成一把私钥，签出来的文件不能导入现版 APK。维护者的签名私钥必须单独保留；公开工具包不含它。因而当前有维护者签发一步，尚非完全自助开户。

## 本机需求与数据流

`session-export.cjs` 只用 Node.js 内置模块；已有 Node 时直接运行，无 npm 依赖、无常驻进程、无开机自启。工具包本身只有文本和脚本；缺 Node 时由 AI 先说明安装影响再处理。

AI 先看到本人登录页面、取得本人同意，再把页面中的学校/学号/房间写入本地观测记录。脚本向公寓智锁现有的 `gy.bostex.net:5500` 或 `applets.bostex.net` 做只读查询，只保留所选本人的一间宿舍。不输入微信密码、验证码、登录 code 或 openid；不修改人员绑定，不发卡，不发开锁或设置命令。

输出资料和官方页面证据应私下交给维护者，不要放在公开仓库、公开群文件或发布包中。维护者运行一次签发命令，程序自动校验输入、重新查询对应权限并输出文件，没有人工确认关卡。这是本机辅助迁移工具，**不提供远程身份认证**；页面截图和摘要不等于官方登录凭据。AI必须读取用户自己的真实已登录页面，不能把“填了学号”声称为成功登录。

## 失败时

没有读到当前本人账号/学校/完整宿舍，停止并补齐实际观测；不要猜字段。观测超过一小时需重读页面。组织额外策略、无有效房间权限、停用设备、过期授权或只提供序列号的锁，可能不适配。文件生成成功也不等于已实测开门。

已绑定过本项目的用户，其已有 `.dormkey` 可按导入教程直接迁移，无需重新采集。其他人的授权文件不能替代自己的文件。
